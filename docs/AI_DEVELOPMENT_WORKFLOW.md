# VOSS - AI DEVELOPMENT WORKFLOW

Version: 1.0

---

# PURPOSE

This document defines exactly how the AI should develop the VOSS project.

The AI must think like a senior full-stack software engineer, software architect, UI/UX designer, database engineer, DevOps engineer, QA tester, and security engineer.

The AI should never behave like a code generator.

The AI should behave like a software development team.

---

# GENERAL RULES

Read every documentation file before writing code.

Understand the project completely.

Never assume requirements.

Follow every document.

Never skip important functionality.

Never ignore previous implementations.

---

# DEVELOPMENT PROCESS

For every feature:

1. Analyze requirements

2. Plan implementation

3. Create required folders

4. Create required files

5. Write clean code

6. Test the feature

7. Fix bugs

8. Optimize code

9. Verify responsiveness

10. Continue to the next task

---

# BEFORE WRITING CODE

Always ask:

Is this reusable?

Is this scalable?

Is this secure?

Is this responsive?

Is this maintainable?

Can this be improved?

---

# UI DEVELOPMENT

Never hardcode layouts.

Use reusable components.

Follow the design system.

Maintain consistency.

Keep spacing consistent.

Use premium animations.

Support all screen sizes.

---

# BACKEND DEVELOPMENT

Create models first.

Then validations.

Then services.

Then controllers.

Then routes.

Then middleware.

Never skip this order.

---

# DATABASE DEVELOPMENT

Design schemas carefully.

Avoid duplicated data.

Use indexes.

Use references properly.

Validate everything.

---

# API DEVELOPMENT

Create RESTful endpoints.

Validate requests.

Return proper status codes.

Handle errors gracefully.

Protect private routes.

---

# TESTING

After every completed feature:

Test frontend.

Test backend.

Test database.

Test API.

Test responsiveness.

Test edge cases.

Fix every issue before continuing.

---

# BUG FIXING

Never ignore bugs.

Never leave TODOs.

Never leave unfinished logic.

Fix problems immediately.

---

# CODE QUALITY

Keep files small.

Keep components reusable.

Avoid duplication.

Use meaningful names.

Comment only complex logic.

---

# GIT WORKFLOW

Commit after every completed feature.

Use meaningful commit messages.

Never commit broken code.

Never commit secrets.

---

# PERFORMANCE

Optimize React rendering.

Optimize MongoDB queries.

Lazy load pages.

Optimize images.

Reduce unnecessary API requests.

---

# SECURITY

Validate all inputs.

Protect every API.

Hash passwords.

Use JWT authentication.

Sanitize user input.

Protect admin routes.

---

✓ No broken pages

✓ No broken routes

✓ No console errors

✓ No API errors

✓ Fully responsive

✓ Production ready

✓ Clean code

✓ Reusable components

✓ Admin panel working

✓ Backend connected

✓ MongoDB connected

✓ Authentication working

✓ Cart working

✓ Checkout working
